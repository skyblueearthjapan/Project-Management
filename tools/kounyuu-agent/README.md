# kounyuu-agent — 購入部品追加依頼 × DOVE連携（WS-C）

設計部員と資材購買担当の間の「追加購入部品の依頼 → 手配 → 回答」の往復を
デジタル化する Windows EXE。**都度起動**。

> 契約: `../../docs/DESIGN_購入部品追加依頼.md`
> 要件: `../../docs/REQUIREMENTS_購入部品追加依頼.md`

## 配布形態: EXE は 1 本

設計部員用・購買用に分けず、**起動時に Windows アカウントを送付先マスタと
突き合わせて画面を切り替える**。

1. EXE が 2 本になるとリビルド漏れのリスクが倍になる（出図EXE で実際に発生した）
2. 役割変更が Excel の 1 列で済む（代理・増員・異動に再配布なしで追随できる）
3. 認証なしの社内前提では 2 本に分けても権限分離にならず、運用コストだけ増える

> 「誰が依頼したか」は Windows アカウントによる**自己申告ベース**であり、
> 厳密な本人証明ではない。社内利用では実務上十分という前提に立っている。

## 何をするか

### 設計部員モード（往路）

1. 工番を選ぶ（DOVE の日程表マスタを検索。**DOVE 未登録の工番も選べる**）
   - 工番が決まっていなければ「工番未定（先行手配）」にチェック
2. 部品リスト Excel を選ぶ
3. 宛先（購買担当）と CC はマスタから自動設定
4. 「確認して送信 → 登録」または「下書きを作成 → 登録」
   - メールは**操作している本人の Outlook アカウント**から送る
   - 部品リストはメールに**添付**され、同じものが DOVE にも保管される

### 購買モード（五十嵐様・復路）

1. 起動すると**未対応の依頼一覧**が出る
   - **工番未定の依頼は先頭に固定**され、背景色でも区別される（手配漏れ防止）
   - 並び順はサーバが決めるので、EXE を直しても壊れない
2. 「部品リストを開く」で Excel を開く
3. 工番が未定の依頼には「工番を紐づける」で後から工番を付けられる
4. 「手配結果を返信 → 完了」でスキャン PDF を選ぶと、依頼元へ返信して完了になる

## セキュリティ規約（CLAUDE.md §2.1 / §2.2）

- ファイルの **copy / move / delete / overwrite / rename を一切行わない**。
  - 部品リスト・スキャン PDF は **読み取ってアップロードするだけ**。元ファイルは触らない。
  - ダウンロードした部品リストは作業フォルダへ**新規作成のみ**（`open(path, "xb")`）。
- Excel（送付先マスタ / 工番マスタ）は `read_only=True` で**読むだけ**。
- 購入依頼は **DOVE 一本**に集約する（TTD には登録しない）。
  ステータスを持つデータを 2 箇所に置くと「片方だけ完了」事故が起きるため。

## 冪等・再送について

`client_request_id` / `client_reply_id`（UUID）を**送信前に 1 回だけ**生成して使う。
メール送信は成功したが DOVE 登録が失敗した場合、**［登録だけ再試行］**で
**メールを再送せずに**登録だけ補完できる。何度押しても依頼・ファイル・送信履歴は重複しない。

## 構成

```
kounyuu_agent/
  main.py          # 設定/マスタ読込 → アカウント判定 → 役割に応じた画面を起動
  account.py       # Windows アカウント取得
  members.py       # 送付先マスタ読込 + 役割判定 + TO/CC 振り分け
  gui_request.py   # 設計部員モード
  gui_purchase.py  # 購買モード
  mailer.py        # 本人アカウントで Outlook 送信 + 本文生成
  dove_client.py   # DOVE API
  kouban.py        # 工番の正規化（★契約点: 親工番 ⇄ 枝番キー）
  master.py        # 工番マスタ Excel 照合
config.example.toml
build.ps1
run_app.py         # PyInstaller エントリ（パッケージ外・必須）
```

### ★ 工番 ID 体系のズレ（`kouban.py` の存在理由）

| | 表記例 |
|---|---|
| 日程表マスタ | `25146-1` … 枝番あり・LW 接頭辞なし |
| DOVE の工番 | `LW25146` … 親工番・LW 接頭辞あり |

この 2 つは直接照合できない。そこで
**DOVE へ送る `job_id` は親工番**、**マスタ照合は枝番付きキー**という二段構えにする。
枝番は本来存在しないはずの例外なので、**構造化せず文字列のまま**依頼レコードに持つ。

## セットアップ（開発）

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[dev,build]"

python -m kounyuu_agent.main
```

`config.example.toml` を `config.toml` にコピーし、環境に合わせて設定する。

## ビルド

```powershell
.\build.ps1
# dist\購入部品追加依頼.exe を生成
```

配布フォルダに `購入部品追加依頼.exe` と `config.toml` を置く
（送付先マスタはファイルサーバを参照するので同梱しない）。

> **重要**: `tools/kounyuu-agent/` に変更を入れたら、必ず
> **「リビルド → 配布先へ差し替え」までを 1 セット**で行うこと。
> config だけ更新して EXE のリビルドが漏れる事故が出図EXE で実際に起きている。
